What is Send Email?

System - Send email sends an email to the system's users: everyone with a chosen role and/or individually selected users. It is meant for service announcements (planned maintenance, new features, policy changes) - not for marketing.

  • Only active users with a valid email address receive it; a user in several chosen roles gets it once
  • Each recipient gets a separate email, so nobody sees the other addresses
  • At most 1000 recipients per send
  • Every send is written to the access logs (subject, message text, chosen roles and users, sent and failed counts)

How to send

  1. Recipients - tick roles (the badge shows how many users each role reaches) and/or search users by name or email and add them
  2. Subject and message - the message is plain text: line breaks are kept and links become clickable
  3. Click Send - a confirmation shows the exact number of recipients (duplicates removed); confirm to send
  4. The email goes out in batches of 20 with a progress bar - keep the page open until it finishes
  5. The result shows how many were sent, which addresses failed, and who was skipped - a user deactivated, removed from the organization or left without an email while the send was running does not get it
  6. If a batch request itself fails (connection lost, session expired), sending stops and is not retried automatically, because part of that batch may already have been sent. The dialog lists that batch as uncertain and shows how many are left; Continue with the rest sends the remaining batches

The email footer shows the website name from Settings.

Organization scope

  • Signed in to the system organization (or a system_coder) - you can send to all users
  • Signed in to any other organization - only that organization's users are listed and receive the email (a notice on the page says so). Switch organizations in the top bar to send to another organization
